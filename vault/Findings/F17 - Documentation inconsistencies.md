# F17 — Documentation inconsistencies

Individually trivial; collectively they made the docs untrustworthy on exactly
the numbers a reader would check first.

| Where | Said | Actually | Status |
|---|---|---|---|
| `README.md` | "**ten** public IDS datasets", LODO "averaged over all 10" | `cross_dataset_matrix.csv` had **nine** columns; the 0.978/0.450/0.528 figures came from a 9-dataset run | fixed — the study now genuinely runs ten, and the numbers are regenerated |
| `demo/run_demo.sh` | "benign + **6** attack types" (twice) | nine attack types | fixed |
| `demo/run_demo.sh` | model "~**55 KB**" | 96 KB | fixed |
| `src/flow_features.py` | "**21**-dim float vector", "The 21 features" (3 places) | 22 | fixed |

| `README.md` | `dataset_maps.py` in the layout | deleted — [[F03 - xgb_edge.onnx exported with the wrong scaler]] | fixed |

## The pattern worth noting

Almost every one of these was a number that *moved* while the prose stayed
still — feature counts, dataset counts, model sizes, attack counts. The
durable fix is not the edits but making the docs derive from the artifacts:

- `BENCHMARK.md` is generated by `demo/benchmark.py`, so its numbers now come
  from `live_meta.json` rather than being retyped
- `live_meta.json` records the split, the scenario counts and the ablation, so
  the caveats travel with the model
- the alignment contract, `FEATURE_UNITS` and `coverage()` are code, not prose,
  so `tests/smoke_test.py` can assert them

The remaining hand-written counts (22 features, ten datasets) are now asserted
in the test suite rather than trusted.
