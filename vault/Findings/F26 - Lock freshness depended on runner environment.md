# F26 — Lock freshness depended on runner environment

## Finding

CI run `33357756792` failed only in `macOS lock freshness`. GitHub's runner set
`PIP_NO_INDEX`; `pip-compile 7.6.1` copied that ambient option into its generated
command comment as `--no-index`. The resolved packages and versions did not
change, but `git diff --exit-code` correctly detected the header-only difference.

This made lock freshness depend on runner configuration even though the lock
contents were reproducible.

## Resolution

All five CI lock-generation commands now pass `--no-header`. The corresponding
lockfiles omit the environment-sensitive autogenerated command comment while
retaining every exact dependency pin and provenance comment.

## Verification

- Regenerated the default macOS locks with `pip-tools 7.6.1` and preserved the
  Linux-only NCCL pin in the Linux x86-64 locks.
- CI regenerates each lock on its declared platform and requires an empty diff.
- Full CI evidence is tracked in [[Remediation 2026-08-22]].
